# Шина ESP32-S3 ↔ ПЛИС: протокол golden

## Физика
- **Шина:** quad SPI, режим 0, ESP — master, half-duplex. Каждый кадр: CS# в 0, команда 8 бит и адрес 24 бита по 4 линиям (8 тактов SCK). Дальше одно из двух:
  - запись: данные от ESP;
  - чтение: 8 dummy-тактов, затем данные от ПЛИС.
- **Порядок бит:** старший нибл первым, бит 7 на IO3.
- **Приём в ПЛИС:** оверсемплинг на 100 МГц, поэтому SCK не выше ~12 МГц. На 80 МГц нужен source-synchronous приёмник (этап после макета).
- **IRQ:** 1, когда golden свободен (не занят флешем или ICAP). У ESP вход с подтяжкой к 0, поэтому выключенная или несконфигурированная ПЛИС читается как «занят».

| Сигнал | ESP32-S3 | ПЛИС i9+ | Гребёнка P3 девборды i5/i9 |
|---|---|---|---|
| SCK | GPIO12 | Y18 (MRCC, банк 14) | 7 (подпись i5: C4) |
| CS# | GPIO10 | W19 (подтяжка вверх) | 9 (C3) |
| IO0 (D) | GPIO11 | Y19 | 12 (A3) |
| IO1 (Q) | GPIO13 | V18 | 13 (B1) |
| IO2 (WP) | GPIO14 | V19 | 17 (C1) |
| IO3 (HD) | GPIO9 | AA20 | 16 (D1) |
| IRQ | **GPIO5** | AA21 | 15 (E2) |
| GND | GND | | 11, 8, 2, 20, 29 |

GPIO46 под IRQ не годится: это стрэпинг-пин. Если ПЛИС держит на нём 1, ESP не входит в режим загрузки прошивки (GPIO0=0 требует GPIO46=0). Для материнки вывод тот же.

## Команды
Номера в коде: `gateware/common/golden_core.sv` (golden), `gateware/common/profile_shell.sv` (профиль), `firmware/ports/esp32s3/components/fpga_link/include/fpga_link.h`.

| Код | Имя | Фаза | Что делает |
|---|---|---|---|
| 01 | ID | чтение 8 | `"FBGL"`, версия, режим (0 golden, 1 профиль), id профиля (2 байта) |
| 02 | STATUS | чтение 8 | [0] бит 0 busy, бит 1 ошибка, бит 2 идёт заливка плоскости, бит 3 на экране плоскость; [1] код ошибки; [2..5] BOOTSTS (BE); [6..7] счётчик кадров видео (BE) |
| 03 | BUF_W | запись ≤8192 | в буфер 8 КБ с адреса `addr[12:0]` |
| 04 | BUF_R | чтение ≤8192 | из буфера |
| 05 | PARAM | запись 8 | len (BE32, ≤ 16 МБ), buf_off (BE32, < 8192) |
| 06 | RESULT | чтение 4 | результат последней операции флеша (CRC, ID, SR) |
| 07 | TUNE | запись 4 (ключ) | `addr[7:0]` передних фронтов SCK до первого нибла, `addr[8]` менять данные по заднему фронту |
| 08 | LA_ARM | запись 4 (ключ) | отладка: захватить следующий кадр анализатором |
| 10 | ERASE64K | — | стереть 64 КБ по `addr` (кратно 0x10000, не ниже 0x400000) |
| 11 | PROG | — | записать len байт из буфера (buf_off) с `addr`, не ниже 0x400000 |
| 12 | READ | — | прочитать len байт с `addr` в буфер (buf_off) |
| 13 | CRC | — | CRC-32 (IEEE) len байт с `addr`, результат в RESULT |
| 14 | FL_ID | — | JEDEC ID флеша в RESULT |
| 15 | FL_SR | — | регистр статуса флеша в RESULT |
| 20 | BOOT | — | WBSTAR = `addr`, IPROG (ICAP) |
| 22 | REBOOT_GOLDEN | запись 4 (ключ) | профиль: IPROG на 0 (нужен ICAP, см. ниже) |
| 30 | CSR_W | запись 4·n | профиль: регистры с индекса `addr[7:0]`, слова старшим байтом вперёд |
| 31 | CSR_R | чтение 4·n | профиль: то же на чтение |
| 32 | STREAM | запись n | профиль: байты в поток канала `addr[7:0]`; обратного давления нет, свободное место ESP читает из регистра профиля |

| 33 | PAD | запись 4 | профиль: кнопки {пад 1, пад 0} по 16 бит, BE; слово принимается целиком по CS#↑ и только при ровно 4 байтах |
| 40 | OSD_RECT | запись ≤8192 | golden: прямоугольник в плоскость меню, см. «Плоскость меню» |
| 41 | OSD_FILL | запись 5 | golden: заливка прямоугольника |
| 42 | OSD_PAL | запись 3·n | golden: палитра с индекса `addr[3:0]`, RGB888 |
| 43 | OSD_CTRL | запись 4 (ключ) | golden: `addr[0]` = 1 показывать плоскость, 0 заставку |

Профиль отвечает на 01 (`"FBPR"`), 07, 22, 30–33. Значение регистров задаёт сам профиль.

## Плоскость меню (golden, версия 2)
Golden выводит HDMI 640×480 60 Гц. Меню рисует супервизор в плоскость 640×480 по 4 бита на пиксель с палитрой 16 × RGB888 (`gateware/common/video/osd_plane.sv`, 38 RAMB36). Пока супервизор не включил плоскость командой 43, на экране заставка: логотип Fabbit 400×95 пикселей в (120, 182), как `boot-640x480` бренд-кита.

- **Адрес** в 40 и 41: `addr = {y[11:0], x[11:0]}`, x чётный.
- **40 OSD_RECT:** w (2 байта), h (2 байта) BE, w чётная, затем пиксели построчно, байт = 2 пикселя, старший нибл левее. Байты сверх w/2·h отброшены. Кадр не длиннее буфера 8 КБ: большой прямоугольник идёт полосами.
- **41 OSD_FILL:** w, h, байт цвета (2 пикселя, можно узор). Заливка идёт после CS#↑, байт за такт 100 МГц: весь экран 1,5 мс. Пока она идёт, IRQ = 0 и STATUS бит 2 = 1; кадр 40 или 41 за это время отброшен целиком.
- **42 OSD_PAL:** по 3 байта R, G, B на цвет, индекс растёт с `addr[3:0]`. До первой записи палитра серая: индекс i = 17·i.
- **43 OSD_CTRL:** ключ `FBKY`, как у флеш-команд, иначе мусор на шине при перезагрузке супервизора прячет заставку.
- Пиксели за краем экрана отброшены. Смена палитры или CTRL посреди кадра портит не больше одного кадра.

Стенд, 10 МГц: FILL 640×480 1,6 мс, RECT 640×480 35 мс (4,3 МБ/с).

## Кнопки (PAD)
Супервизор опрашивает кнопки 1 кГц и шлёт PAD при каждой смене и повтором раз в 100 мс, только когда в ПЛИС профиль (ID `"FBPR"`). От смены кнопки до конца кадра PAD на стенде 115–129 мкс. Раскладка одинакова для всех ядер, как `cont1_key` Analogue Pocket. Ядро переводит её в свой контроллер само.

| Бит | Кнопка | Бит | Кнопка |
|---|---|---|---|
| 0 | Вверх | 8–13 | L1, R1, L2, R2, L3, R3 (на приборе нет) |
| 1 | Вниз | 14 | Select |
| 2 | Влево | 15 | Start |
| 3 | Вправо | | |
| 4 | A: правая кнопка ромба | 5 | B: нижняя |
| 6 | X: верхняя | 7 | Y: левая |

Кнопки прибора: крестовина → биты 0–3, F1 (верх) → X, F2 (право) → A, F3 (низ) → B, F4 (лево) → Y, Меню → Start, Назад → Select. Fn — модификатор: пока она нажата, игра кнопок не видит. Кнопки, нажатые вместе с Fn, остаются скрыты от игры до отпускания.

| Сочетание | Действие |
|---|---|
| Fn нажата и отпущена одна | меню поверх игры |
| Fn + Меню | сброс ядра |
| Fn + Назад | выход в golden (команда 22) |

NES (`gateware/profiles/nes/nes_pad.sv`): A → A, B → B, X → турбо A, Y → турбо B, турбо 10 Гц (3 кадра нажато, 3 отпущено). Противоположные направления вместе снимаются.

### Стенд: кнопки на ESP32-S3 DevKitC-1 N16R8
Кнопка замыкает ножку на GND, подтяжка внутри ESP. Все на гребёнке J3.

| J3 | GPIO | Кнопка | | J3 | GPIO | Кнопка |
|---|---|---|---|---|---|---|
| 4 | 1 | F2, право ромба | | 15 | 45 | Вниз |
| 5 | 2 | F1, верх | | 16 | 48 | Вправо |
| 6 | 42 | F4, лево | | 17 | 47 | Вверх |
| 7 | 41 | F3, низ | | 18 | 21 | Влево |
| 8 | 40 | Назад | | | | |
| 9 | 39 | Меню | | | | |
| 10 | 38 | Fn | | | | |

Нельзя: GPIO35–37 (J3-11…13) заняты octal PSRAM модуля R8 (даташит ESP32-S3-WROOM-1, с. 12, сноска b), кнопка на них ломает PSRAM и ESP уходит в перезагрузку. GPIO19/20 (J3-20/19) — USB консоли. GPIO0 (J3-14) — стрэп загрузки. GPIO45 — стрэп VDD_SPI: при сбросе нужен 0 (3,3 В), внутренняя подтяжка вниз это даёт, нажатая кнопка тоже.

ERASE, PROG, BOOT, TUNE и LA_ARM исполняются только при ровно 4 байтах данных `FBKY` в кадре (защита от мусора на шине, ошибка 5). Команды без данных исполняются, когда CS# поднимается. Флеш-команда, пришедшая, пока golden занят, даёт ошибку 3.

**Коды ошибок:** 0 нет, 1 защищённая область, 2 параметр, 3 занят, 4 неизвестная команда, 5 нет ключа.

**Двойная буферизация:** пока PROG пишет из одной половины буфера, ESP грузит следующие 4 КБ в другую через BUF_W и PARAM. Эти команды разрешены и в состоянии busy.

## ICAP и тулчейн
openXC7 (prjxray-db 2026-09) собирает ICAPE2, но в железе он не работает: регистры читаются 0, IPROG не действует. Проверено 7 вариантов: верхний и нижний сайт, перестановка бит, инверсия CSIB/RDWRB. Поэтому:
- **golden** собирается в Vivado: `make golden_vivado` в `gateware/`;
- **профили** собираются openXC7 или Vivado (`make viv_<цель>`). Из профиля openXC7 в меню можно вернуться только перезапуском питания модуля, профиль Vivado возвращается командой 22.
